# 敏感数据发现

扫出代码、配置、测试数据里的**个人敏感信息** —— 身份证、银行卡、手机号、邮箱。

**带校验位验证**，不是纯正则 —— 像手机号的订单号、Luhn 不过的假卡号都不会误报。

## 一、何时用

- 把代码仓库转为公开前
- 交接、外包、离职时清点
- 上线前、提交测试数据前
- 合规审查（《个人信息保护法》要求）
- 怀疑真实用户数据被带进了仓库

## 二、它查什么

| 级别 | 类型 | 校验方式 |
|---|---|---|
| 🔴 高 | 身份证号 | GB 11643-1999 **加权校验位**（17 位加权和 mod 11）|
| 🔴 高 | 银行卡号 | **Luhn 算法** |
| 🟡 中 | 手机号 | 号段白名单 + **边界断言**（防从长数字里截一段）|
| 🟢 低 | 邮箱地址 | 结构匹配（常见且往往正当，标为提示）|

## 三、为什么不是「正则一扫就完事」

因为**误报是安全工具的头号杀手**。纯正则找手机号/身份证会命中：
订单号、时间戳、版本号、随机 ID、哈希片段……

本工具对每个类型都做**结构 + 校验位**双重验证：
```
✅ 11010519491231002X  合法身份证（校验位对）
❌ 11010519491231003X  校验位错 → 不报
✅ 4532015112830366    合法卡号（Luhn 通过）
❌ 4532015112830367    改一位，Luhn 不过 → 不报
❌ 138123456789012345  像手机号但 18 位 → 不报
❌ 注释行里的示例         → 不报
```

## 四、它**不会**做的事

**输出永不包含原值** —— 只记「文件:行 + 类型 + 打码后的片段」。
记原值等于让扫描工具自己成为泄露源。

## 五、怎么用

```bash
<cli 路径>                 # 扫当前目录
<cli 路径> --demo          # 看检出效果
<cli 路径> --html r.html   # HTML 报告
```

**退出码 1 = 有高危命中**。

## 六、边界

- **不是「数据分类分级」工具** —— 只发现，不判定该数据属于什么级别。
- **不扫二进制/图片**：只读文本文件。截图里的身份证、PDF 里的表格扫不到。
- **不查 .git 历史**：只能看到当前工作区。已提交过的敏感数据需要另做历史清理。
- **邮箱误报较多**：代码仓库里邮箱常常正当（联系方式、LICENSE 署名），标为「低」。
- 与 `dsh-secret-scan` **不重叠**：那个查密钥/凭据，这个查个人信息。

## 七、覆盖面

4 类敏感信息 + 对应校验算法。
不覆盖：护照号、驾驶证、地址、生物特征、健康数据。
